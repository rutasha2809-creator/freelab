## 1. Что это за проект

**Freelance** (до 27.09.2026 назывался «Фрилаб») — веб-приложение на чистом HTML/CSS/JS
без фреймворков и сборки. Трекер заказчиков и платежей для фрилансера: карточки
клиентов, календарь поступлений, учёт налога НПД (4%/6%) по клиентам «по договору».

Владелец продукта и основной пользователь — Наталия (rutasha2809@gmail.com),
фрилансер-финансовый консультант. Вход по email/паролю (Supabase Auth), потому что
сайт публичный (GitHub Pages).

**Важно про аудиторию.** 27.09.2026 Наталия переформулировала цель: приложение делается
не только под неё, а **для фрилансеров вообще** — «оно должно быть удобно и понятно даже
для студента, который на фрилансе подрабатывает». Отсюда два следствия, которые надо
держать в голове при любых правках:
- не перегружать интерфейс отчётами и цифрами, оставлять только то, чем реально пользуются;
- тон и оформление — не «финансовый отчёт», а яркое и живое: фрилансеры в большинстве
  люди творческие, ей нужен «ВАУ-эффект». Сдержанный серый минимализм она уже отвергла
  прямым текстом, равно как и пёструю «детскую раскраску» до него. Текущая система —
  это найденный компромисс, ломать его без запроса не надо.

**Все денежные расчёты идут через `amountOf(p)`** в `js/app.js`: по оплаченной записи
берётся `fact_amount`, если он задан, иначе `amount`. Не считать суммы напрямую из
`p.amount` — иначе плитки, налог и отчёт разойдутся с календарём.

Галочка «получено» в строке платежа ничего не сохраняет сама: она открывает запись
с подставленными сегодняшней датой и плановой суммой в поле факта, курсор сразу в
сумме. Салют показывается при сохранении, когда запись действительно стала оплаченной.

Уникальное ограничение `payments_client_date_task_auto_unique UNIQUE
(client_id, plan_date, task, auto_generated)` — защита от повторной генерации
автоплатежа (см. «Грабли»).

**Подтверждение e-mail выключено** (Authentication → Sign In / Providers → User Signups →
Confirm email, 28.09.2026). Причина: встроенная почта Supabase шлёт **не больше двух писем

регистрация с Яндекса», хотя почтовый домен ни при чём.

Сейчас регистрация сразу выдаёт сессию и пускает в приложение, письма при регистрации
не отправляются вовсе. Лимит остаётся только на сброс пароля — там письмо всё ещё нужно.
Если понадобится вернуть подтверждение или снять лимит совсем — подключать свой SMTP
(Яндекс/Mail.ru/Resend) в Authentication → Emails → SMTP Settings.

Настройки авторизации **не меняются через MCP-коннектор** — только в панели Supabase.
Наталия сама туда не ходит: это делается за неё в её браузере (Claude in Chrome), где
она уже авторизована.

Имя пользователя хранится **не в таблице**, а в метаданных Supabase Auth:
`sb.auth.updateUser({ data: { display_name } })`. Отдельная колонка для этого не нужна.

Ключи Supabase (anon/publishable) захардкожены в начале `js/app.js` — это нормально,
это публичный anon-ключ, доступ ограничивается RLS-политиками, а не секретностью ключа.

## 4. Структура приложения

Четыре экрана, переключение — нативным атрибутом `hidden` (см. критичный CSS-фикс в п.9):

1. **Заставка** `#intro` — полноэкранный оверлей, четыре сцены (п.8).
2. **Экран входа** `#authScreen` — слева рассказ о приложении с анимацией пересчёта
   купюр и гайдом из трёх шагов, справа форма входа/регистрации/сброса пароля.
3. **Приложение** `#app` — четыре раздела, переключаются без перезагрузки:
   - **Календарь** (главный) — месячная сетка поступлений с источниками по дням,
     клик по дню открывает детали; выше — четыре плитки статистики (bento-сетка),
     полоса «собрано за месяц» и план по налогу. Листание месяцев стрелками
     синхронно меняет и плитки, и календарь.
   - **Клиенты** — карточки в одну строку: иконка с инициалами, имя, кнопки
     редактировать/удалить. Больше в карточке ничего нет — это её явное требование.
   - **Доход** (раньше «Отчёты») — три плитки (получено / налог НПД / на руки),
     столбчатый график дохода по месяцам и таблица.
   - **Настройки** — компактные строки с иконками: имя, email, тема, экспорт,
     импорт, сброс данных.
4. **Модальные окна** — клиент, платёж, детали клиента, детали дня, запрос имени
   при первом входе.

Плюс **плавающая кнопка (FAB)** в правом нижнем углу — быстрая запись платежа
с любого экрана.

При первом входе, если имя не задано, показывается модалка `#nameModal`. Имя пишется

зашивать её имя или данные в код.

## 6. Автоматический график платежей

Приложение само генерирует ожидаемые платежи **на 6 месяцев вперёд**
(`SCHEDULE_HORIZON_MONTHS = 6`) по данным карточки клиента — ей остаётся отмечать факт.

- `computeScheduledOccurrences(client, fromISO, toISO)` — считает даты и суммы
  (monthly/weekly, аванс+остаток, «прилипание» дня к последнему дню месяца,
  если дня не существует — например 31 в феврале).
- `syncClientSchedule(client)` — сверяет существующие автоплатежи с графиком и
  **добавляет только недостающее** через
  `upsert(..., { onConflict: 'client_id,plan_date,task,auto_generated', ignoreDuplicates: true })`.
- `syncAllSchedules()` — вызывается при каждой загрузке данных, «дотягивает» график
  по мере того, как проходит время (rolling horizon).
- `clearFutureAutoPayments(clientId)` — при редактировании карточки удаляет ещё не
  наступившие и не оплаченные автоплатежи, после чего график строится заново.
  Оплаченные и добавленные вручную записи не трогает никогда.

## 7. Дизайн-система

Стекло + живой фон + свечение. Токены в `:root` и `:root[data-theme="dark"]`
в начале `styles.css`.

- Палитра построена на одной градиентной гамме: фиолетовый `#7C5CFF` → малиновый
  `#C061FF` → розовый `#FF5CA8`, акцент-бирюза `#2BB9AE`.
- **Тёмная тема — по умолчанию.** Светлая включается, только если её выбрали явно:
  `if (savedTheme !== 'light') → dark`. Предпраинтовый инлайн-скрипт в `<head>`
  ставит атрибут до первой отрисовки, чтобы не было вспышки.
- Фон живой: `.aurora` (три дрейфующих градиентных пятна) + `.grain`
  (SVG-шум поверх). Поверхности — стекло: `--paper` + `backdrop-filter: var(--blur)`.
- **Цветом выделяется только просрочка**, и только когда она не ноль. Ноль — обычным
  цветом текста. Разноцветные инициалы клиентов, разноцветные суммы налога и «на руки»
  она отвергла прямым текстом. Инициалы — один градиент на всех.
- Цифры анимируются от предыдущего значения, а не от нуля (`lastAnimatedValues` +
  `data-animate-key`) — иначе при листании месяцев кажется, что меняются и те
  показатели, которые на самом деле не изменились.
- `font-variant-numeric: tabular-nums` на всех анимированных числах, иначе прыгает ширина.
- Везде есть `@media (prefers-reduced-motion: reduce)` — не ломать это при правках.
- **Выпадающие списки.** Список вариантов `<select>` рисует операционная система, он не
  наследует фон элемента. Поэтому есть отдельные непрозрачные токены `--menu-bg` /
  `--menu-fg` и `color-scheme: dark` на тёмной теме. Полупрозрачный `--paper` для
  `option` не годится — будет системный белый фон.

**Рисовать реалистичные фигуры (руки, лица, тела) координатами кривых вслепую нельзя** —
получится стилизация, и Наталия это сразу увидит. Так уже было три раза. Для реализма —
только обводка фотографии по конвейеру выше.

Пропустить заставку можно кнопкой `#introSkip`, клавишей Esc или кликом; клик по сцене

## 9. Публикация изменений — пошаговый процесс

У ИИ **нет git push credentials** в этой среде (осознанное ограничение окружения) —
`git push` из `device_bash` всегда упадёт с `fatal: could not read Username for
'https://github.com'`. Предлагать инструмент `add_repo` не стоит: 27.09.2026 она этот
запрос отклонила. Процесс такой:

1. Отредактировать файлы локально в рабочей папке сессии
   (`/mnt/user-data/outputs/freelab/...`).
2. Если менялась структура БД — выполнить миграцию самому через
   `mcp__Supabase__apply_migration`. Наталию об этом не просить.
3. **Поднять версию в cache-busting параметрах** `css/styles.css?v=N` и `js/app.js?v=N`
   в `index.html` — для каждого изменённого файла. Текущую версию смотреть в файле,
   не считать в уме. На 29.09.2026 это **v53** для css и app.js (i18n.js — v4, voice.js — v1, fonts.css — v1, vendor/supabase.js — v1).
4. Записать файлы через `mcp__remote-devices__device_commit_files`
   (`devicePath: "C:\\Users\\rutas\\OneDrive\\Документы\\FREELAB\\..."`, `force: true`).
5. **Обязательно подождать 8–10 секунд и проверить через `device_bash` (`grep`), что
   содержимое реально обновилось.** OneDrive иногда репортит успех раньше, чем файл
   физически долетает. Не говорить, что всё готово, пока это не подтверждено.
6. Закоммитить локально: `cd "$HOME/mnt/FREELAB" && git add -A && git -c user.name=... commit -m "..."`.
   Предупреждения `LF will be replaced by CRLF` безобидны.
   **Проверять `git status` перед `add -A`** — в папке могут лежать посторонние файлы
   (так однажды в репозиторий уехал черновик `hand-animation-preview.html`).
7. **Явно сказать Наталии**, что можно запускать `ОБНОВИТЬ САЙТ.bat`. Она не должна
   гадать сама — это её прямое требование.
8. Напомнить про Ctrl+F5 при первом открытии.

- **Задержка синхронизации OneDrive.** `device_commit_files` может вернуть `"written"`
  до того, как файл долетит до диска. Всегда `sleep 8` + `grep` после записи.
- **Забытый cache-busting.** Поднимать версию у каждого изменённого файла.
- **C2PA-метаданные при передаче картинок.** Передача SVG/PNG через `device_commit_files`
  впрыскивает метаданные происхождения — favicon раздулся с 489 байт до 8 КБ.
  Обход: писать такие файлы через `device_bash` heredoc.
- **Контейнер не видит `github.io`.** Прокси-аллоулист не пускает — проверять
  опубликованный сайт curl'ом из контейнера бесполезно.
- **CSS-специфичность `[hidden]`.** Атрибут `[hidden]` с `display: none` из UA-стиля
  проигрывает любому авторскому классу с `display`. Исправлено глобально в начале
  `styles.css`: `[hidden] { display: none !important; }`. Если элемент «не скрывается,
  хотя `hidden` стоит» — искать новый конфликтующий `display`-селектор.
- **Порядок правил в стеклянном слое.** `.tile { background: var(--paper) }` шло
  *после* `.tile--dark` с той же специфичностью и перекрывало акцентный градиент —
  подпись на первой плитке сливалась с фоном. Акцентные варианты переобъявлены
  в конце. При добавлении новых «стеклянных» правил проверять, что они не перекрывают
  акцентные плитки. **Та же ловушка повторилась с `.modal__panel`**: он стоял в общем
  списке стеклянных поверхностей, из-за чего сквозь окно просвечивал дашборд. Панели
  модалок выведены из этого списка и используют непрозрачные `--panel-bg` / `--panel-line`.
- **Два открытых окна сразу.** Переход из окна дня в редактирование платежа не закрывал
  окно дня — они накладывались. Любое действие, открывающее вторую модалку, должно
  сначала вызвать `closeModals()`.
- **Контраст.** Белый текст на `#FF5CA8` давал 2,2 при норме 4,5. Градиент акцента
  притушён до `#6A4AE6 → #8B3FD4 → #C42A78` (4,6–4,9). Любой новый цветной фон под
  текстом проверять расчётом, а не на глаз.
- **Гонка при входе → дубли автоплатежей.** Исправлено флагом `loadedForUserId` плюс
  уникальным ограничением в БД и `ignoreDuplicates: true`.
- **Селекторы кнопок в календаре.** `.calendarNav button { width: 28px }` заодно ловил
  кнопку «Сегодня» и обрезал её текст. Скоупить такие правила по конкретному классу.
- **`position: fixed` и `offsetParent`.** У фиксированных элементов (FAB) `offsetParent`
  равен null — проверка видимости через него даёт ложный отрицательный результат.
- **Лимит писем Supabase.** Встроенная почта — 2 письма в час на проект, дальше
  `429: email rate limit exceeded`, причём пользователь не создаётся. Диагностируется
  через `query_logs` по `source = 'auth_logs'`. Английские ошибки Supabase переводятся
  функцией `authErrorText()` — новые тексты ошибок добавлять туда, а не показывать сырое.
- **Потеря признака `auto_generated` при редактировании → дубли.** Форма записи
  собирала `draft` без `autoGenerated`, и `paymentToRow` ставил `false`. Отредактированный
  автоплатёж становился «ручным», планировщик переставал считать его своим и создавал на
  ту же дату вторую запись — она висела в просрочке рядом с оплаченной. Уникальное
  ограничение не спасало, потому что `auto_generated` входит в ключ. Исправлено дважды:
  признак берётся из прежней записи, а `syncClientSchedule` считает дату занятой **любой**
  записью клиента, а не только автосозданной. При любых правках формы платежа проверять,
  что `draft` не теряет служебные поля.
- **Git-локи в папке OneDrive.** После одного из коммитов в `.git` остались `HEAD.lock`,
  `index.lock` и `objects/*/tmp_obj_*` — git не смог их удалить, потому что удаление в
  подключённой папке по умолчанию запрещено. Такие локи ломают `ОБНОВИТЬ САЙТ.bat`.
  Лечится `device_request_delete_permission` на папку проекта и `rm -f`. После каждого
  коммита стоит смотреть, не осталось ли `.git/*.lock`.
- **Не путать «карточка клиента» и «платежи».** Поля дня и периодичности в карточке —
  входные данные для генератора графика, сами по себе не платежи.

22. Голосовая запись (кнопка микрофона, Web Speech API, ru-RU): фраза разбирается в `js/voice.js`, форма записи открывается уже заполненной, под ней строка «Вы сказали: …». 24. Налоговый режим (Настройки → «Налоги»): `taxSettings` {mode: npd|flat|none, rate} хранится в `user_metadata.tax`; `clientTaxRatePercent` и `taxName()` учитывают режим. В режиме «Не считать налог» скрыты налоговый прогноз, плитки и колонки отчёта; при не-НПД скрыты поля «по договору / кто платит».
25. Валюты: `clients.currency` (text, default 'RUB'); основная валюта — `user_metadata.currency`. Валюта платежа = валюта его заказчика (`payCur`). Суммы разных валют НЕ складываются: итоги, налог, отчёт и графики считаются для выбранной `viewCurrency` (`inView(p)`), переключатель `.curSwitch` виден при >1 валюты. `formatMoney(n, cur)` без `cur` использует `viewCurrency`; для строк платежей и клиентов всегда передаём валюту явно. Пересчёта по курсу нет намеренно (решение Наталии).
26. Напоминания об оплате (только в приложении, Capacitor LocalNotifications; в браузере раздел скрыт по решению Наталии): включаются кнопкой в настройках (`localStorage freelab-reminders`), для каждого неоплаченного платежа планируются уведомления в 10:00 в день плана («Сегодня ожидается поступление») и на следующий день («Оплата не поступила»); ближайшие 60 (лимит iOS 64), перепланируются в `renderAll()` → `scheduleReminders()`. Android 13+ требует POST_NOTIFICATIONS (добавляется в workflow).
23. Частичная оплата: если фактическая сумма меньше плановой, открывается окно «Остаток» («Получено меньше плана. Не хватает X ₽.») и создаётся новая запись на остаток с пометкой «(остаток)». Формулировки согласованы с Наталией (нейтральный род).

## 14. Мобильное приложение (iOS и Android) — Capacitor

Решение Наталии (29.09.2026): упаковывать текущий сайт оболочкой **Capacitor** — один код для сайта, iOS и Android.
Монетизация на старте — разовая покупка; платные функции и другую модель можно добавить позже (через встроенные покупки магазинов).

Что лежит в репозитории:
- `package.json`, `package-lock.json` — Capacitor 8, плагины status-bar и speech-recognition, @capacitor/assets.
- `capacitor.config.json` — `appId` **com.example.freelance — ВРЕМЕННЫЙ**, обязательно заменить до первой публикации (после публикации менять нельзя). `appName` — Freelance.
- `scripts/build-www.mjs` — собирает `www/` из файлов сайта (отдельной копии кода нет).
- `resources/` — иконка (`icon-only.png`, исходник `icon.svg`) и заставка (`splash*.png`); `npm run assets` раскладывает их по размерам.
- `icons/`, `manifest.webmanifest` — иконки и манифест для установки сайта на экран телефона (PWA).
- `mobile-ci/android.yml` — заготовка (пока НЕ в `.github/workflows`, чтобы отказ GitHub принять workflow-файл не сломал публикацию сайта): ручная сборка тестового `.apk` в GitHub Actions (Actions → Run workflow → скачать артефакт). Папки `android/`, `ios/` в репозиторий не кладём: Actions создаёт их заново (`.gitignore`).
- Шрифты (`fonts/`, `css/fonts.css`) и библиотека Supabase (`js/vendor/supabase.js`) теперь лежат локально — приложение не зависит от Google Fonts и CDN.
- Отступы под «чёлку»: `viewport-fit=cover` и `env(safe-area-inset-*)`.
- Голос: в оболочке нет `SpeechRecognition`, поэтому `makeNativeSpeech()` в `app.js` подключает системное распознавание через плагин (тот же интерфейс, остальной код не менялся). Ещё не сделано (по порядку): аккаунты Apple Developer ($99/год) и Google Play Console ($25); сборка iOS (нужен macOS-раннер GitHub Actions + сертификаты); реальный appId; политика конфиденциальности (URL) и удаление аккаунта внутри приложения (требование Apple); скриншоты и описание для магазинов; встроенная покупка (разовая); проверка Apple-гайдлайна 4.2 (не «просто сайт в обёртке»).

### Важно: названия плановых платежей
Автоматические платежи («Аванс», «Остаток», «Плановый платёж») **всегда хранятся в базе по-русски** — это часть ключа защиты от дублей
(`client_id, plan_date, task, auto_generated`). На экране название переводится через `t(p.task)`. Нельзя сохранять в базу результат `t()`
для таких названий: при смене языка получатся дубли (так было в v47, исправлено в v48). Язык по умолчанию — русский; английский включается в настройках.

### Заставка (инфографика)
Три сцены (форма заказа, календарь, итоги) нарисованы как SVG-карточки в стиле приложения прямо в `index.html` (блоки `.iArt`).
Цифры «печатаются» и считаются скриптом `runFx` в `app.js` (атрибуты `data-type` и `data-count`), остальное — CSS-анимации `fx-*` в `styles.css`.
Тексты внутри рисунков — только числа и слова из словаря (`Получено`, `Налог`, `На руки`); других надписей добавлять не нужно, иначе их придётся переводить.
